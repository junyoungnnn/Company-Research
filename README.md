# Company Research · 디섹 Tech Radar

기업·기술 모니터링, 출처 기반 보고서, 선박 설계 적용 검토를 위한 웹 앱입니다.
Node.js 24 표준 라이브러리만 사용하므로 npm 패키지 설치 없이 실행합니다.

## 실행

```sh
node server.mjs
```

http://127.0.0.1:5173 에 접속합니다. `.env.example`을 참고해 환경 변수를 설정하세요. `.env` 파일을 만들었다면 `node --env-file=.env server.mjs`로 실행할 수 있습니다. 실제 비밀번호와 API 키는 GitHub에 올리지 마세요.

## 구현 기능

- 기업 등록·수정·분류, 산업/적용 업무/키워드/검토 메모
- Google News RSS 수집과 중복 제거, 발표일·수집일 구분, 실패 기록
- 원문 링크·요약 수동 등록, 유용함/관련 없음/PoC 검토 피드백
- 보고서 버전 보존, Markdown 다운로드, 이전 보고서 대비 새 근거 수
- AI 웹 검색 기반 기업 분석, 디섹 적용 가설·PoC·제약·변화 요약
- 미등록 기업 후보와 추천 근거, 검토 후 관심 기업 등록
- 최근 7일 수집량 추이와 카테고리 필터
- 단계별 검토 보드
- 서버 측 한국 시간 일일 예약 작업, 재시작 후 당일 미실행 작업 보완
- 클라우드 접근 보호용 HTTP Basic 인증(HTTPS 배포 필수)

## AI 설정

서버에 `OPENAI_API_KEY`와 `AI_MODEL`을 설정하면 **AI 조사 실행**을 사용할 수 있습니다. 모델은 해당 계정에서 Responses API의 `web_search`와 Structured Outputs를 지원하는 모델을 선택해야 합니다. 기본 모델을 강제하지 않습니다.

AI 호출은 유료일 수 있습니다. 회사에서 승인한 계정과 사용 한도를 설정하세요. 기본적으로 한 실행에 기업 최대 5개와 분야 탐색 1회를 조사하며, 기업 수가 많으면 마지막 AI 조사일이 오래된 순으로 순환합니다. `MAX_AI_COMPANIES_PER_RUN`으로 1~30개 범위를 조절합니다.

검색 도구가 반환한 출처 URL과 일치하는 자료만 저장합니다. AI 결과는 여전히 담당자 검토가 필요합니다. 적용성은 내부 시스템을 모르는 예비 평가입니다. 기업의 공개 조사 필드와 이전 출처 자료만 보내며 내부 메모·적용 업무 필드는 보내지 않습니다. 공개 조사 필드에도 내부 정보를 입력하지 마세요.

- 공식 API 문서: https://developers.openai.com/api/docs/guides/tools-web-search
- 구조화된 출력: https://developers.openai.com/api/docs/guides/structured-outputs

## Docker 클라우드 배포

GitHub Pages는 서버 코드를 실행하지 않으므로 이 앱의 운영 환경으로 사용할 수 없습니다. Docker를 지원하는 서버 또는 웹 서비스에서 저장소를 빌드합니다.

```sh
docker build -t company-research .
```

클라우드에서 반드시 설정할 항목:

| 설정 | 설명 |
|---|---|
| PUBLIC_ORIGIN | 실제 HTTPS 서비스 주소. 끝 슬래시 제외 |
| APP_USER | 로그인 이름 |
| APP_PASSWORD | 16자 이상 비밀번호. 서버의 Secret 저장소에 보관 |
| DATA_DIR | 영구 디스크 경로. Docker 기본 /data |
| OPENAI_API_KEY | AI 서비스 키. Secret으로 보관 |
| AI_MODEL | 계정에서 사용할 모델 ID |
| SCHEDULE_ENABLED | true이면 일일 작업 활성 |
| SCHEDULE_AI | true이면 RSS에 이어 AI 조사 실행 |
| SCHEDULE_HOUR_KST | 한국 시간 실행 시각. 기본 7 |

컨테이너 포트는 8080이며 `/health`가 상태 확인 경로입니다. 영구 디스크를 `/data`에 마운트하고, 컨테이너 사용자 node(UID 1000)가 쓸 수 있게 설정하세요. 플랫폼의 HTTPS 프록시를 사용하고 인스턴스는 **1개**로 유지하세요. 현재 파일 저장 방식은 여러 인스턴스 동시 쓰기를 지원하지 않습니다. 서버가 절전/중단되는 플랜에서는 정시 실행이 보장되지 않습니다.

모든 팀원은 현재 같은 APP_USER/APP_PASSWORD를 사용합니다. 개인별 계정·SSO·세분화된 권한·감사 로그는 다음 단계입니다. 민감한 내부 자료를 다루기 전에 회사의 운영 기준에 맞춰 확장해야 합니다.

예약은 날짜별 한 번 시작합니다. 실패 작업은 수집 이력에 남으며 수동 재실행할 수 있습니다. 긴 작업 도중 서버가 종료되면 완료 상태를 보장하지 않으므로 이력을 확인하세요. 정시 실행을 요구하는 운영 환경에서는 상시 서버와 외부 스케줄러/작업 큐로 확장하세요.

외부 스케줄러를 쓸 경우 `JOB_TOKEN`을 Secret으로 설정하고 `POST /api/jobs`에 `Authorization: Bearer <JOB_TOKEN>`, JSON `{"ai":true}`를 전송할 수 있습니다. 내부 예약과 중복되지 않도록 하나만 활성화하세요. 응답은 작업 시작(202)이며 실제 완료는 수집 이력에서 확인합니다.

## 검증과 제한

```sh
node --test test.mjs
```

데이터 영속성·중복 제거·보고서 버전·추천 저장, 출처 없는 AI 응답 거부, 내부 메모 미전송, HTTP 인증·교차 출처 거부를 테스트합니다.

로컬 환경의 Zscaler 인증서 문제로 실제 외부 RSS/AI 호출은 검증되지 않았습니다. AI는 모의 응답으로 검증했습니다. 배포 후 실제 수집, AI 호출, 서버 재시작 후 데이터 보존, 예약 실행을 확인해야 합니다. GitHub에 소스를 올리는 것만으로 클라우드 배포나 AI 계정 설정이 완료되지 않습니다.

`data/`, 로그, 인증서, API 키는 소스에 포함하지 않습니다. 데이터 백업은 운영 서버에서 별도로 수행하세요.
